// ==============================================================
// 强势盘策略 —— 两个版本
// ==============================================================
//
// 【code.js】v1.8.0 硬条件版（在跑的稳定版）
//   20 个条件全 AND：平台白名单 + 年龄 1~500 分钟 + 市值<12w + Top10 15~30%
//   + 创建者/推特/团队/内鬼/捆绑等防雷项 + 钱包结构 + 买入次数>50
//   + 偏离 2~120% + AO 上升 + AC 上升
//   注意：v1.8.0 里 creatorTokenBal==0 与 人均买入次数<2.6 算了但没进 checks（历史遗漏），
//   打分版里已分别恢复为硬否决 / 转为打分项。
//
// 【code-score.js】score-v1.5.0 打分版（影子模式验证中）
//   两层结构，顺序不可颠倒：
//     第一层·硬否决（3 条，一票否决，不参与打分，不能被任何高分补偿）：
//       平台白名单 + AO + AC（动量确认，维持 v1.8.0 原布尔判定 aoOk/acOk）。
//       AO 与 AC 本质是同一个"动量确认"信号的两个观测角度（AO 定方向、AC 是 AO 的
//       导数确认同一方向），不是两个独立维度——不拆开打分，合在硬否决里当一个前提；
//       和平台白名单一样，是"必须过"的强指标。
//       （v1.5 之前，年龄/创建者/推特/团队/内鬼/捆绑/垃圾钱包等 9 条防雷项也在这一层，
//       v1.5 把它们挪进了第二层打分组——见下方说明。）
//     第二层·硬否决全部通过后，才进入加权梯形打分（19 项，全部平权、每项权重=1，
//       总分>=60 触发）：原有 10 项（市值、Top10持仓%、买入次数、人均买入次数、高频钱包%、
//       新钱包%、老钱包%、新钱包率%、机器人degen率%、偏离%）+ v1.5 新挪进来的 9 项防雷项
//       （年龄秒、年龄分、创建者发币数、创建者持仓数量、推特改名次数、开发团队持仓%、
//       内鬼%、捆绑买入率%、垃圾钱包%）。这 9 项本身是有程度差异的风险信号（内鬼占比
//       9% 和 0.1% 都算"过线"但风险不一样），全 AND 一票否决会让"擦边"和"极端"一样
//       被整盘拒绝，挪进打分组后单项擦边不再整盘放弃，能靠其它维度补分——注意这是实质性
//       放宽，如果某一项在你看来无论如何都不能商量，应该退回第一层硬否决。
//       权重目前全部平权，没有再区分"筹码结构/资金行为/偏离"这种主观大小分配
//       （那套比例来自 v1.8.0 拍的初值，没有真实回测数据支撑，与其误导人不如先平权，
//       等攒够数据再按 |AUC-0.5| 重配）。
//   缺失口径：字段缺失记 0 分（显式 null 也算缺失，不会被 Number(null)=0 蒙混）。
//
// 日志标记（机器可解析，供后续校准）：
//   SCORE=77.5 VER=score-v1.5.0 GRADE=A
//   GRADE: S = 总分>=85 强信号 | A = 60~85 标准信号 | - = 未过线或被硬否决
//   （硬否决没过时 GRADE 强制为 '-'，SCORE 仍原样输出打分部分的真实得分，
//    避免"被拒的却标着强信号"的自相矛盾——分数高不能替代动量确认/白名单这些强制项）
//   正则一把抠出：/SCORE=([\d.]+) VER=(\S+) GRADE=(\S)/
//
// ==============================================================
// 调参闭环（review 工具「回测·因子」面板）
// ==============================================================
// 边界原则：review 是字段分析工具、策略是策略。AO/AC 动量逻辑属于策略侧，
// 靠实盘日志与盘感调；review 只回答"哪些快照字段在什么区间对高倍有区分度"。
//
// 每日流程：
//   1. 导出当天 calls + snapshots → review 上传（自动存入浏览器 IndexedDB，逐天积累）
//   2. 「回测·因子」tab：选高倍阈值（默认 5x）→ 扫描原字段 → 勾高 lift 且校正后显著的字段
//      （相关性黄标提示的重复因子二选一）
//   3. 看回测（十分位/阈值扫描）+ 时间外推验证（验证段明显衰减 = 过拟合，别上实盘）
//   4. 「生成策略打分代码」→ 与 code-score.js 现有参数对照，人工决定是否替换区间/权重
//   5. 「策略」tab 粘贴 code-score.js 回放：打分因子表看
//      差此一项（最该调的因子）/ 依赖此项（失灵风险）/ 区分效果（反向 = 因子在帮倒忙）
//
// 待校参数（当前均为拍的初值）：各因子满分核与硬界、权重、CUTOFF=60、GRADE 分级线 85。
// AO/AC/平台白名单是硬否决，不在待校打分参数之列——除非明确要放宽"必须过"这个前提，
// 否则调参只动第二层的区间/权重/CUTOFF。
